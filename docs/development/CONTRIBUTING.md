# Contribución

1. Parte de la rama acordada y crea una rama de alcance reducido.
2. Mantén los cambios de app separados de los cambios de Odoo salvo que el contrato entre ambos se entregue y pruebe conjuntamente.
3. Ejecuta `flutter analyze` y los tests afectados.
4. Revisa traducciones, accesibilidad, permisos y errores de red.
5. No incluyas secretos, archivos de firma, keystores, `key.properties`, credenciales Firebase ni capturas con datos personales.
6. En el PR indica los controladores/modelos Odoo implicados, perfiles probados y límites pendientes.

La infraestructura de CI, revisores obligatorios y estrategia de versiones no está determinada a partir del repositorio.
